\section{Introduction}
\emph{Jungle Rest Stop} is a real-time 3D scene made with OpenGL 3.3. A small rest stop stands in a
clearing of a thick jungle, next to a parking lot and a road. The main rule of the course is followed
everywhere: \textbf{every object is built only from basic shapes} (cube, cylinder, sphere, cone, torus,
wedge and a few more) placed with translation, rotation and scaling. No 3D model files and no image
files are loaded; all shapes and all textures are made by the program.

\section{The Basic Shapes}
Everything is built from the small set of \emph{unit} meshes in \Cref{tab:shapes}. Each one is
centred at the origin with a size of about one unit. They are created once at start-up
(\texttt{gfx/Shapes.cpp}) and kept on the GPU.

The curved shapes come from simple parametric formulas. For a cylinder (radius $r$, angle
$\theta_i = 2\pi i/n$):
\[
\mathbf{p}_i^{top} = (r\cos\theta_i,\ 0.5,\ r\sin\theta_i),\qquad
\mathbf{p}_i^{bottom} = (r\cos\theta_i,\ -0.5,\ r\sin\theta_i),\qquad
\mathbf{n}_i = (\cos\theta_i,\ 0,\ \sin\theta_i).
\]
A sphere uses $\mathbf{p}(\phi,\theta) = 0.5\,(\sin\phi\cos\theta,\ \cos\phi,\ \sin\phi\sin\theta)$ with
normal $\mathbf{n}=2\mathbf{p}$. A torus uses
$\mathbf{p}(u,w) = (R + r\cos w)(\cos u, 0, \sin u) + (0, r\sin w, 0)$. The coil follows the helix
$\mathbf{c}(t) = (R\cos 2\pi k t,\ R\sin 2\pi k t,\ L(t-0.5))$, and a small circle is placed around each
point of it.

\subsection{The vertices of each shape}\label{sec:vertices}
This part lists the exact vertices that are stored on the GPU. Every object in the scene is
only a copy of one of these lists, moved by a matrix (\Cref{sec:worked}).

\paragraph{Round shapes (vertices come from a formula).} A round shape has too many vertices to
write by hand, so they come from a loop over an angle. The cylinder, cone and truncated cone use the
same loop with $n$ steps, $\theta_i = 2\pi i/n$ for $i=0\dots n$, bottom radius $r_b=0.5$ and top radius $r_t$:
\[
\mathbf{p}_i^{top} = (r_t\cos\theta_i,\ 0.5,\ r_t\sin\theta_i),\qquad
\mathbf{p}_i^{bot} = (0.5\cos\theta_i,\ -0.5,\ 0.5\sin\theta_i).
\]
Each pair of neighbours makes one side quad $(\mathbf{p}_i^{bot},\mathbf{p}_{i+1}^{bot},\mathbf{p}_{i+1}^{top},\mathbf{p}_i^{top})$.
A cap is a centre vertex $(0,\pm0.5,0)$ plus the ring, joined as a fan of triangles. For example, the
first vertices of the 24-sided cylinder are $\mathbf{p}_0^{top}=(0.5,0.5,0)$,
$\mathbf{p}_1^{top}=(0.483,0.5,0.129)$, $\mathbf{p}_2^{top}=(0.433,0.5,0.25)$ and $\mathbf{p}_6^{top}=(0,0.5,0.5)$.

\section{Transformations and Hierarchical Modelling}
\subsection{The three basic transformations}
All matrices are $4\times4$ and column-major, so they can go straight to OpenGL.
\[
T(t)=\begin{bmatrix}1&0&0&t_x\\0&1&0&t_y\\0&0&1&t_z\\0&0&0&1\end{bmatrix}\quad
S(s)=\begin{bmatrix}s_x&0&0&0\\0&s_y&0&0\\0&0&s_z&0\\0&0&0&1\end{bmatrix}\quad
R_y(\theta)=\begin{bmatrix}\cos\theta&0&\sin\theta&0\\0&1&0&0\\-\sin\theta&0&\cos\theta&0\\0&0&0&1\end{bmatrix}
\]
$R_x$ and $R_z$ work in the same way. Rotation about any axis $\mathbf{a}$ uses Rodrigues'
formula $R = \cos\theta\,I + (1-\cos\theta)\,\mathbf{a}\mathbf{a}^T + \sin\theta\,[\mathbf{a}]_\times$.
The camera uses the usual \texttt{lookAt} view matrix and a perspective projection
\[
P = \begin{bmatrix}\frac{1}{a\tan(f/2)}&0&0&0\\0&\frac{1}{\tan(f/2)}&0&0\\0&0&-\frac{z_f+z_n}{z_f-z_n}&-\frac{2z_fz_n}{z_f-z_n}\\0&0&-1&0\end{bmatrix},
\]
where $f$ is the field of view, which the user changes with the mouse wheel (see \Cref{sec:camera}).

\subsection{Order of operations}
Every part of every object is placed with
\[
M_{part} = M_{parent}\cdot T(\text{position})\cdot R(\text{rotation})\cdot S(\text{size}).
\]
The unit shape is first \textbf{scaled} to the right size, then \textbf{rotated}, then
\textbf{moved} to its place inside the parent, and finally the parent's own matrix carries it
into the world. Normals use the normal matrix $N = (M^{-1})^T$ (upper $3\times3$ part), which keeps
lighting correct even when a shape is stretched.

\paragraph{C. Jointed models: the knee of a person and the car door.}
A person is a chain of nodes (\Cref{fig:humangraph}). The knee of the man's left leg is found with
\[
\mathbf{p}_{knee} = \underbrace{T(\mathbf{p})R_y(\psi)}_{\text{person}}\cdot
\underbrace{T(0,0.93,0)}_{\text{pelvis}}\cdot
\underbrace{T(0.092,-0.03,0)\,R_x(\theta_{thigh})}_{\text{hip}}\cdot
\underbrace{T(0,-0.45,0)}_{\text{knee}}\cdot(0,0,0).
\]
$R_x(\theta)$ maps $(x,y,z)\mapsto(x,\ y\cos\theta - z\sin\theta,\ y\sin\theta + z\cos\theta)$. In
person space:
\begin{itemize}
  \item standing, $\theta_{thigh}=0$: knee at $(0.092,\ 0.90-0.45,\ 0) = (0.092,\ 0.45,\ 0)$;
  \item walking, leg forward, $\theta_{thigh}=-26^\circ$: $(0.092,\ 0.90-0.45\cos26^\circ,\ 0.45\sin26^\circ) = (0.092,\ 0.496,\ 0.197)$.
\end{itemize}
The knee moves 20 cm forward and 4.6 cm up, and the shin and the foot follow it because they are
its children. The thigh itself is a truncated cone flipped by $R_x(180^\circ)$, which maps
$(x,y,z)\mapsto(x,-y,-z)$: the wide bottom ring vertex $(0.5,-0.5,0)$ becomes, after
$S(0.17,0.45,0.17)$, $R_x(180^\circ)$ and $T(0,-0.225,0)$, the point $(0.085,0,0)$, which is at the hip.
So the wide end of the thigh is at the top, like a real leg.

The woman uses exactly the same chain; her model only has $S(0.95)$ at the root and a width
factor $0.94$, so her hip is at $x=0.092\times0.94=0.086$.

The \textbf{car door} works the same way with $R_y$. Its hinge is at $\mathbf{h}=(-0.905,0,0.73)$ in car
space, and the outer door panel is a cube with $S=(0.04,0.534,1.0)$ and $T=(-0.01,0.582,-0.5)$ inside
the door node $T(\mathbf{h})R_y(\theta_{door})$. The rear-bottom corner $v_0=(-.5,-.5,-.5)$ becomes
$(-0.03,0.315,-1.0)$ in door space. Then, with $R_y(\theta)$: $x'=x\cos\theta+z\sin\theta$, $z'=-x\sin\theta+z\cos\theta$:
\begin{itemize}
  \item door closed, $\theta=0^\circ$: $(-0.03,0.315,-1.0)+\mathbf{h} = (-0.935,\ 0.315,\ -0.27)$;
  \item door open, $\theta=70^\circ$: $(-0.950,\ 0.315,\ -0.314)+\mathbf{h} = (-1.855,\ 0.315,\ 0.416)$.
\end{itemize}
The back edge of the door swings 92 cm out to the side and moves forward, while the points on the
hinge line do not move at all.

\paragraph{Windows: a matrix made straight from the corner points.}
Car windows are not rectangles, so they are not made with $T\cdot R\cdot S$. Instead the matrix is
built from the corner points the window must have. For a parallelogram with corners $\mathbf{a}$,
$\mathbf{b}$, $\mathbf{d}$ (and $\mathbf{b}+\mathbf{d}-\mathbf{a}$):
\[
M = \begin{bmatrix} \mathbf{b}-\mathbf{a} & \mathbf{d}-\mathbf{a} & t\,\hat{\mathbf{n}} & \mathbf{a}+\tfrac12(\mathbf{b}-\mathbf{a})+\tfrac12(\mathbf{d}-\mathbf{a}) \\ 0&0&0&1\end{bmatrix},
\qquad \hat{\mathbf{n}}=\frac{(\mathbf{b}-\mathbf{a})\times(\mathbf{d}-\mathbf{a})}{|(\mathbf{b}-\mathbf{a})\times(\mathbf{d}-\mathbf{a})|}
\]
where $t$ is the glass thickness. Then the cube corner $(-.5,-.5,0)$ lands exactly on $\mathbf{a}$,
$(.5,-.5,0)$ on $\mathbf{b}$ and $(-.5,.5,0)$ on $\mathbf{d}$. A triangle is done the same way with
the wedge: $w_1\to\mathbf{p}_0$, $w_0\to\mathbf{p}_1$, $w_2\to\mathbf{p}_2$. Each side window is one
parallelogram plus one triangle (a small quarter glass at the front, or a painted panel at the back),
so no glass sticks out past the pillars.

\paragraph{D. Plants: the root fins of a rainforest tree.}
A tree has 4 buttress fins around its trunk. Fin $i$ is a wedge with $S=(0.13,1.5,1.2)$ and
$T=(0,0.75,0.6)$ inside a node turned by $R_y(90^\circ i)$ (plus a small random angle):
\begin{itemize}
  \item bottom-front vertex $w_0=(-.5,-.5,.5)$: $S\to(-0.065,-0.75,0.6)$, $T\to(-0.065,0,1.2)$, then $R_y(90^\circ)\to(1.2,\ 0,\ 0.065)$;
  \item top-back vertex $w_2=(-.5,.5,-.5)$: $S\to(-0.065,0.75,-0.6)$, $T\to(-0.065,1.5,0)$, then $R_y(90^\circ)\to(0,\ 1.5,\ 0.065)$.
\end{itemize}
So each fin starts on the trunk 1.5 m above the ground and reaches the ground 1.2 m away from it,
and the four $R_y$ angles spread the fins around the tree. Grass and ferns are cross cards placed
with $T(\mathbf{p})R_y(\text{random})S(w,h,w)$: the card vertex $(0.5,1,0)$ becomes the tip of a
blade at height $h$.

\subsection{The \texttt{Node} helper}
Objects are written as trees of \texttt{Node}s. A child node only stores the extra transform
relative to its parent, so moving the parent moves all its children too.
\begin{lstlisting}
struct Node {
    DrawSink* sink;  Mat4 M;                         // M = this node's world matrix
    Node at(const Vec3& p, const Vec3& rotDeg) const // child: M * T(p) * R(rot)
        { return Node(*sink, rotateYXZ(translate(M, p), rotDeg)); }
    Node rotX(float deg) const { return rot(deg, Vec3(1,0,0)); }
    void part(MeshId mesh, Vec3 pos, Vec3 size, const Material& m, Vec3 rotDeg = {}) const
        { sink->add(mesh, scale(rotateYXZ(translate(M, pos), rotDeg), size), m); }
};
// Example: a sofa arm = a box plus a "rolled" cylinder lying along Z
n.box({x, 0.42f, 0.0f}, {0.16f, 0.44f, 0.88f}, fabric);
n.part(M_CYLINDER, {x, 0.64f, 0.0f}, {0.19f, 0.88f, 0.19f}, fabric, {90, 0, 0});
\end{lstlisting}
The same object code can send its shapes to different ``sinks'': the static world, the per-frame
list, a counter (for the tables in this report), or a collector that keeps every part so it can be
drawn alone (for the parts catalogues).

\paragraph{How it works.} Each machine is a small \emph{state machine} (\Cref{fig:vendsm}).
Money is kept as an integer number of Taka, so there are no rounding errors. When you press
\textbf{OK}, the spiral turns $360^\circ$ in 1.6 s, and the products move forward by one place
($0.075$ m). The front product then becomes a free body with velocity $\mathbf{v}$, gravity
$g = 9.81\,\mathrm{m/s^2}$ and spin. When it hits the tray floor it bounces with restitution 0.32:
\[
\mathbf{v}_{y} \leftarrow \mathbf{v}_{y} - g\,\Delta t,\qquad \mathbf{p}\leftarrow\mathbf{p}+\mathbf{v}\,\Delta t,\qquad
\text{if } p_y < y_{floor}:\ v_y \leftarrow -0.32\,v_y .
\]
When the bounce speed drops below $0.35$ m/s, the product lies on its side and waits. Pushing the
flap rotates it inward around its top hinge, and the item goes into the player's bag. Any change
falls as coins into the coin cup. An empty slot is refilled automatically after 40 s.

\textbf{Placement.} The world ($280\times280$ m) is covered with a \emph{jittered grid} of 6.6 m cells.
Each cell gets one random point. Points inside the cleared area (building, lot and road with a margin)
are skipped. A random number then picks the species: 40\% rainforest tree, 18\% palm, 7\% giant,
8\% bamboo, 11\% banana, 8\% bush, and 8\% nothing. Every cell also gets 1--5 ferns or bushes and
4--12 grass or flower tufts (more at the edge of the clearing). There is a 12\% chance of a rock and a
5\% chance of a log. In total the jungle has \statJungleTrees\ broad-leaf trees, \statPalms\ palms,
\statBamboo\ bamboo clumps, \statBushes\ bushes, \statFerns\ ferns, \statGrass\ grass tufts,
\statRocks\ rocks and \statLogs\ logs. Every trunk also gets a circle collider.

\textbf{Terrain.} The ground is one displaced grid. It is flat in the clearing and along the road,
and becomes gently hilly further away:
\begin{align*}
H(x,z) &= 14\,\big(\mathrm{fbm}(0.018x,\,0.018z)-0.45\big) + 1.2\,\mathrm{fbm}(0.07x,\,0.07z) \\
h(x,z) &= \max\!\Big(-1.5,\ H(x,z)\cdot \mathrm{smoothstep}(0,30,d)\cdot \mathrm{smoothstep}\big(5,14,|z-z_{road}(x)|\big)\Big)
\end{align*}
Here $d$ is the distance outside the clearing. The road is straight through the lot
($z=16$) and curves in the jungle. With $t=|x|-30$:
\[
z_{road}(x)=16 + 7\sin(0.035\,t)\,\mathrm{sign}(x)\cdot \mathrm{smoothstep}(0,25,t).
\]
The smoothstep factor makes the bend start gently (its slope is 0 at $t=0$). Without it the road had a
sudden $14^\circ$ kink at $|x|=30$, and a wedge-shaped gap opened between two road boxes there. The road is
built from 2 m long boxes turned to follow the curve; neighbouring boxes overlap by 40 cm, which covers
the small gap on the outer side of every bend. \Cref{fig:tour_first} shows the clearing in the jungle.

\section{Lighting and Shading}
\subsection{Illumination model}
The \textbf{illumination model} says how much light leaves a point of a surface. We use the
\textbf{Phong illumination model} with Blinn's half vector (the \emph{Blinn--Phong} model). It adds three
kinds of reflected light:

\begin{table}[H]
\centering\small
\caption{The three terms of the Phong illumination model}\label{tab:phongterms}
\begin{tabularx}{\linewidth}{@{}P{1.8cm}P{4.6cm}X@{}}
\toprule
Term & Formula & Meaning \\ \midrule
Ambient & $I_a\,k_a$ & light that has bounced around the scene; it reaches every surface, even in shadow, so nothing is fully black \\
Diffuse & $I_l\,k_d\,\max(\mathbf{N}\cdot\mathbf{L},0)$ & \textbf{Lambert's cosine law}: a surface facing the light is bright, one at a grazing angle is dark. It looks the same from every viewing direction (matte paint, cloth, wood) \\
Specular & $I_l\,k_s\,\max(\mathbf{N}\cdot\mathbf{H},0)^{n}$ & the shiny highlight. It moves when the camera moves. A large shininess $n$ (chrome: 128) gives a small sharp spot, a small $n$ (fabric: 8) a wide dull one \\
\bottomrule
\end{tabularx}
\end{table}

Here $\mathbf{N}$ is the unit normal, $\mathbf{L}$ the unit vector to the light, $\mathbf{V}$ the unit vector
to the camera and $\mathbf{H} = \operatorname{normalize}(\mathbf{L}+\mathbf{V})$ the half vector. Phong's
original model uses the mirror direction $\mathbf{R}=2(\mathbf{N}\cdot\mathbf{L})\mathbf{N}-\mathbf{L}$ and
$(\mathbf{R}\cdot\mathbf{V})^n$; Blinn's $(\mathbf{N}\cdot\mathbf{H})^n$ gives almost the same picture,
is cheaper and has no sharp cut-off at wide angles. For one light the classic equation is
\[
I = I_a k_a + I_l\big(k_d\max(\mathbf{N}\!\cdot\!\mathbf{L},0) + k_s\max(\mathbf{N}\!\cdot\!\mathbf{H},0)^{n}\big).
\]
Our shader uses the same equation, summed over all lights, with a few extra factors.
For one light with direction $\mathbf{L}$:
\[
C = \underbrace{\text{mix}(A_{ground},A_{sky},\tfrac{N_y+1}{2})\,k_d}_{\text{ambient}}
 + \sum_{lights}\Big(k_d\max(\mathbf{N}\!\cdot\!\mathbf{L},0) + k_s(\mathbf{N}\!\cdot\!\mathbf{H})^{n}\Big)\,I\,a(d)\,c\,s
 + E .
\]
Here $k_d$ is the surface colour (times the texture), $k_s$ is the specular strength, $n$ is the
shininess, $I$ is the light colour times its intensity, $a(d)$ is the attenuation, $c$ is the spot cone
factor, $s$ is the shadow factor and $E$ is the emission (screens, LEDs, bulbs). The ambient part uses
\emph{hemisphere} lighting: surfaces facing up get the sky colour and surfaces facing down get the
ground colour. Inside the building the ambient part is multiplied by 0.45, because the roof blocks
the sky. Leaves and grass use soft ``wrap'' lighting, $0.6\,\mathbf{N}\!\cdot\!\mathbf{L}+0.4$, and are
lit from both sides. When you look towards the sun through leaves, a \emph{translucency} term
$0.45\,k_d\,I\,s\,\max(-\mathbf{V}\cdot\mathbf{L},0)^3$ makes them glow yellow-green, like real thin
leaves. Leaf cards are also a little darker at their base (a cheap kind of ambient occlusion).

\textbf{Attenuation} uses a smooth window, so every light really ends at its range $r$ and can be skipped
beyond it:
\[
a(d) = \frac{\big[\mathrm{clamp}(1-(d/r)^4,\,0,\,1)\big]^2}{1+d^2},\qquad
c = \mathrm{smoothstep}\big(\cos\theta_{out},\ \cos\theta_{in},\ -\mathbf{L}\cdot\mathbf{D}\big)\ \text{for spot lights.}
\]

\subsection{Shiny materials: polished metal and glossy paint}\label{sec:shiny}
Every material has its own $k_s$ and shininess $n$: fabric, plaster and bark are almost matte
($k_s\approx0.05$, $n\approx8$), wood and leather are a little shiny, marble and the floor tiles are
glossy ($n\approx90$). Two kinds of material get an extra term, because real metal and lacquer mostly show
\emph{what is around them}:
\begin{itemize}
  \item \textbf{Polished metal (chrome)}: the chrome sculpture next to the entrance, the waste bins, the canopy
        posts, the car wheel rims and handles. The diffuse part is made weak ($0.25\,k_d$), the highlight is strong
        and has the metal's colour, and the surface reflects its surroundings.
  \item \textbf{Glossy lacquer (car paint)}: normal coloured paint with a clear coat on top. The clear coat adds a
        sharp white highlight and a reflection that becomes stronger at grazing angles.
\end{itemize}
The reflected direction is $\mathbf{R} = \operatorname{reflect}(-\mathbf{V},\mathbf{N}) = 2(\mathbf{N}\cdot\mathbf{V})\mathbf{N}-\mathbf{V}$.
No real reflection is traced; instead the colour seen in direction $\mathbf{R}$ is a simple painted
surrounding $E(\mathbf{R})$: bright sky above, a thin dark band of jungle at the horizon, sunlit ground below,
and the glow of the sun (inside the building: ceiling, walls and floor). The amount of reflection uses
Schlick's Fresnel approximation, $F = (1-\mathbf{N}\cdot\mathbf{V})^5$, which is large when you look along the
surface:
\[
C_{metal} = \text{Phong}(0.25\,k_d,\ 3k_d) + E(\mathbf{R})\,k_d\,(0.85+0.15F),\qquad
C_{paint} = \text{Phong}(k_d,\ 2.5) + E(\mathbf{R})\,(0.08+0.75F).
\]

\subsection{Shading: where the equation is evaluated}
The illumination model gives the light at \emph{one} point. The \textbf{shading model} decides at which
points it is computed and how the colour is filled in across a triangle:
\begin{table}[H]
\centering\small
\caption{The three classic shading methods}\label{tab:shading}
\begin{tabularx}{\linewidth}{@{}P{2.6cm}XP{3.2cm}@{}}
\toprule
Method & How & Look \\ \midrule
Flat shading & one normal per triangle, the equation is used once, the whole triangle gets one colour & faceted, every triangle visible \\
Gouraud shading & the equation is used at the 3 vertices (vertex shader), the colours are blended across the triangle & smooth, but highlights in the middle of a triangle are lost or smeared \\
\textbf{Phong shading} (ours) & the \emph{normal} is blended across the triangle, and the equation is used at every pixel (fragment shader) & smooth, sharp correct highlights \\
\bottomrule
\end{tabularx}
\end{table}
We use \textbf{Phong shading}. The vertex shader sends the world position and the normal
$N\,\mathbf{n}$ (with the normal matrix $N=(M^{-1})^T$) to the fragment shader; the GPU interpolates them
across the triangle, and the fragment shader normalises the normal again and evaluates the lighting.
Whether a shape looks smooth or faceted depends on its \emph{vertex normals}, not on the shading method:
a cube has separate vertices for each face with the face normal, so each face is flat and the edges are
sharp; a sphere or cylinder has one normal per vertex pointing straight out, so it looks round even with
only 20 or 24 sides (see the shapes in \Cref{sec:vertices}). In Basic mode the same Phong shading is
used, only without textures, shadows and fog.

\subsection{Choosing lights every frame}
The shader accepts up to 16 point and 8 spot lights. Every frame the light manager:
\begin{enumerate}
  \item drops lights that are switched off, too far away ($>45$ m beyond their range), or whose sphere of
        influence is outside the camera frustum,
  \item keeps the closest ones,
  \item sorts them by \textbf{region}: ATM room, lounge, library or outdoors.
\end{enumerate}
Each pixel works out its own region from its position and loops \emph{only} over the lights of that
region. This has two benefits. Light no longer leaks through walls into the next room, and pixels do
much less work. In the lounge view this change raised the frame rate from 53 to 63 FPS.

\section{Day and Night}
A 24-hour clock runs at 1 game hour per 20 s by default (keys change the speed, pause it, or jump
between day and night). The sun's direction comes from the hour:
\[
a=\frac{hour-6}{12}\pi,\qquad \mathbf{s}=\operatorname{normalize}(0.95\cos a,\ \sin a,\ 0.42),\qquad
\mathbf{m} = \operatorname{normalize}(-0.8\,s_x,\ -s_y,\ 0.3).
\]
So the sun rises in the east ($+x$) at 6:00, is highest at noon and sets at 18:00, and the moon is on
the opposite side. All other values are blended from the sun height $s_y$: the sky zenith and horizon
colours (with an orange glow near sunrise and sunset), the sun colour (warm when low), the ambient
light, the fog colour and density, the cloud colour and the exposure. The night factor
$1-\mathrm{smoothstep}(-0.14,\,0.10,\,s_y)$ shows the stars and moon, turns on the street lamps and car
headlights, and wakes up the fireflies. \Cref{fig:daytimes} shows the same view at four times of day.

\section{Textures}
\subsection{Procedural textures}
All 25 textures are created at start-up from \emph{value noise}. Random values are placed on a grid and
smoothly interpolated between grid points. Several octaves are then added together (fractal
Brownian motion):
\[
\mathrm{fbm}(\mathbf{p}) = \frac{\sum_{i=0}^{k-1} 0.5^{i}\,\mathrm{noise}(2^{i}\mathbf{p})}{\sum_{i=0}^{k-1}0.5^{i}} .
\]
The noise wraps around at the texture border, so the textures tile without seams. Patterns are built
on top of it: rows of bricks with mortar, wooden planks with grain $\sin(6v+\text{noise})$, tiles with
grout, marble veins, woven fabric, bark ridges, and also \emph{cut-out} textures (leaves, grass blades,
fern, palm frond, flowers, vine) whose alpha channel marks where the leaf is.

\begin{figure}[H]\centering\includegraphics[width=0.92\linewidth]{textures}\caption{All procedural textures ($*$ = alpha cut-out, light grey shows the transparent part).}\end{figure}

\subsection{How textures are applied}
\begin{itemize}
  \item All layers live in one \texttt{GL\_TEXTURE\_2D\_ARRAY} ($256\times256$, mip-maps, $4\times$
        anisotropic filtering). Each instance only stores a layer number, so a texture change never
        breaks an instanced draw call.
  \item A texture stores a \emph{detail} value. The final colour is
        $k_d = \text{colour}\times 2\cdot\text{texel}$, so the same brick texture works for any brick colour.
  \item \textbf{Object-space box mapping}: the shader picks the plane of the largest normal component
        and uses the local position multiplied by the object's scale:
        $(u,v) = (x,z)$, $(z,y)$ or $(x,y)$ times the repeats per metre. A 10 m wall therefore shows ten
        times more bricks than a 1 m box, without any UV work.
  \item Cut-out cards use their mesh UVs, and pixels with $\alpha<0.5$ are discarded (also in the shadow pass,
        so leaves cast leaf-shaped shadows).
  \item The terrain mixes two textures (lawn grass and forest floor) using a large-scale noise and the
        distance from the clearing.
\end{itemize}

\section{Shadows}
Shadows use \textbf{shadow mapping} (\Cref{fig:shadowidea}).
\begin{enumerate}
  \item \textbf{Depth pass}: the scene is drawn from the sun with an orthographic camera
        ($\pm32$ m box around the player, 2048$\times$2048 depth texture, so one texel is about 3 cm). Only depth is stored.
  \item \textbf{Main pass}: every pixel is moved into the light's space,
        $\mathbf{p}_{L} = P_L V_L\,(\mathbf{p}+0.05\,\mathbf{N})$. If its depth is larger than the stored depth,
        it is in shadow.
\end{enumerate}
To make the shadows look good:
\begin{itemize}
  \item a slope-scaled bias $0.0006+0.0012(1-\mathbf{N}\cdot\mathbf{L})$, a 5 cm normal offset and a polygon offset
        in the depth pass remove ``shadow acne'',
  \item \textbf{PCF}: 5 hardware-compared samples (the centre counts twice) give soft edges,
  \item no shimmering: the light box moves only in whole shadow-map texels (along the light's own axes), and the
        sun direction used for shadows changes only in steps of $0.5^\circ$, so shadow edges do not crawl,
  \item glass, grass and other tiny details do not cast shadows, which saves time.
\end{itemize}

\section{Sky, Fog, Tone Mapping and Wind}\label{sec:sky}
\begin{itemize}
  \item \textbf{Sky}: one full-screen triangle. For each pixel the view ray is rebuilt from the inverse
        view-projection matrix. The colour is $\text{mix}(horizon, zenith, h^{0.55})$, plus a sun disc
        ($\max(\mathbf{d}\cdot\mathbf{s},0)^{900}$) with a glow, a moon, twinkling stars (a hash on a
        3D grid) and moving clouds (4-octave noise projected on a sky plane).
  \item \textbf{Fog}: $f = 1-e^{-(d\rho)^{1.5}}$ blends to the horizon colour. It hides the end of the world
        and gives a humid jungle look. The density is higher at night and lower when the camera is high up.
  \item \textbf{Tone mapping}: $C' = 1-e^{-C\cdot exposure}$ keeps bright lamps from turning flat white.
        The exposure rises at night, like an eye adapting to the dark.
  \item \textbf{Wind}: leaves and grass sway in the vertex shader. The offset grows with the height
        inside the shape: $\Delta x = 0.05\,h\,\min(s_y,2.5)\sin(1.7t+0.35x+0.27z)$.
        Aquarium plants reuse this as a water current.
\end{itemize}

\section{Interaction: Using the Machines}
\subsection{Look-and-press picking}
Every button, slot, flap, switch, TV or aquarium registers an \emph{oriented box} (its matrix $M$ and half
size $\mathbf{h}$) every frame. A ray goes from the camera through the centre of the screen. For each box
the ray is moved into the box's own space with $M^{-1}$, and the \emph{slab test} is applied on each axis:
\[
t_1=\frac{-h_a-o_a}{d_a},\quad t_2=\frac{h_a-o_a}{d_a},\qquad
t_{near}=\max_a\min(t_1,t_2),\quad t_{far}=\min_a\max(t_1,t_2).
\]
The ray hits the box if $t_{near}\le t_{far}$ and $t_{near}$ is within reach (2.4 m). The closest box
wins. Its prompt is shown under the crosshair (for example ``Insert Tk 10 coin''), and it glows. Pressing
\textbf{E} or the left mouse button runs its action. As an automatic test, the program aims the camera at
fourteen different parts and records what it hits (\Cref{lst:probes}). Every part was hit correctly.

\subsection{Driving and parking}
Cars follow \emph{paths}: lists of points with the running length $s$. The car's position comes from
interpolation at $s$, and its heading from the direction of the segment. The road path samples
$z_{road}(x)$ every 3 m. Parking uses a cubic Bézier curve
\[
\mathbf{B}(t) = (1-t)^3\mathbf{P}_0 + 3(1-t)^2t\,\mathbf{P}_1 + 3(1-t)t^2\,\mathbf{P}_2 + t^3\mathbf{P}_3,
\]
with $\mathbf{P}_0=(x_s+5,16)$ and $\mathbf{P}_1=(x_s+2.2,16)$ along the aisle, and
$\mathbf{P}_2=(x_s,z_s\pm2.8)$ and $\mathbf{P}_3=(x_s,z_s)$ in the spot. The tangents at both ends therefore
match the aisle and the spot, so the turn is smooth. Leaving uses a second curve driven in
\emph{reverse} (the heading is the motion direction $+180^\circ$, the reverse lights are on), and then
the car drives forward to the west end of the road.

\textbf{Speed} is limited by the place (9 m/s on the road, 4 m/s in the lot, 1.8 m/s while parking,
1.3 m/s while reversing) and by the distance $s_{left}$ still to go:
$v\le\sqrt{2\cdot2.2\cdot s_{left}}+0.25$, so cars brake smoothly. A car stops if another car is less
than 7.5 m ahead in its lane, or if a person (NPC or player) is less than 5.5 m ahead. Only one car may
park or unpark at a time: it must hold the ``lot token''. Cars in the aisle wait while the token holder
moves in front of them, and a car only starts to reverse when the aisle behind it is clear. These two
rules prevent deadlocks.

\subsection{Walking and activities}
Inside the building, people walk on a waypoint graph of 18 nodes and 22 edges (doorways, room hubs,
the queue entrance at the ATM, and so on). The shortest route is found with \textbf{Dijkstra's
algorithm}, and the route to the car is added at the end. Walking speed is 1.35 m/s, and people wait
if the player blocks them. Every visitor has a plan of 1--3 activities. Each one \emph{reserves} its
resource first (a machine, a seat, a reading spot), so two people never use the same thing:
\begin{itemize}
  \item \textbf{Vending}: walk to the machine, press the keys (press pose), wait for the drop, bend down,
        take the item and carry it. This really runs the machine's state machine.
  \item \textbf{Coffee}: choose a drink, wait, take the cup and carry it.
  \item \textbf{ATM}: run a complete ATM session. The ATM ``presses its own buttons'' with small pauses,
        so the screen shows every step.
  \item \textbf{Sit and watch TV} (7 sofa seats) or \textbf{read} (2 library armchairs) for 12--28 s.
  \item \textbf{Browse books} or \textbf{watch the fish}.
\end{itemize}

\subsection{All the AI in one table}

\paragraph{Fish.} Each of the 7 fish has an angle $\varphi$ that grows with its own speed,
$\varphi \mathrel{+}= \omega\,\Delta t$ ($\omega$ is positive or negative, so some swim the other way). Its
position is on an ellipse inside the tank, $x=r_x\cos\varphi,\ z=r_z\sin\varphi$, and it always faces the
direction it moves: $yaw=\operatorname{atan2}(\Delta x,\Delta z)$. Its height moves slowly towards a target,
$y_{target} = y_0 + 0.03\sin(0.7t+\varphi)$, at most 0.25 m/s. When you press ``Feed the fish'', 12 food
crumbs appear at the surface and sink; while there is food, $y_{target}$ becomes the water surface, so all
fish swim up to eat. The tail is a child node that wags with $R_y(25^\circ\sin(9t+3\varphi))$.

\paragraph{Birds.} 9 birds fly on circles (radius 10--28 m, height 16--30 m) above the jungle:
$\mathbf{p} = \mathbf{c} + (r\cos a,\ h + 1.5\sin 2a,\ r\sin a)$ with $a \mathrel{+}= \omega\Delta t$. A bird is
a body sphere and a cone beak, and the two wings are cubes in child nodes rotated by
$R_z(\pm35^\circ\sin(\text{flap}))$, so they flap.

\paragraph{Fireflies.} 110 small glowing spheres. Their positions are wrapped into a $60\times60$ m box around
the camera ($x' = ((x - x_{cam}) \bmod 60) - 30 + x_{cam}$), so there are always some near the player, and
they drift on sine curves. Each one blinks with $0.5+0.5\sin(3t+3\varphi)$ and is hidden when this is
below 0.25. They are only drawn at night and never inside the building.

\subsection{Particles}
A particle is a tiny basic shape with a position $\mathbf{p}$, a velocity $\mathbf{v}$ and a life time.
Every frame: $\mathbf{v} \mathrel{+}= \mathbf{g}\,\Delta t$ (if it falls), $\mathbf{p} \mathrel{+}= \mathbf{v}\,\Delta t$,
life $\mathrel{-}= \Delta t$; when the life is over it is removed.

\subsection{Text rendering}
All text (HUD, ATM and vending screens, TV, signs, price tags) uses one \textbf{font atlas}:
\begin{enumerate}
  \item At start-up, Windows GDI draws the 95 printable ASCII characters (Consolas font) into one bitmap.
        The bitmap becomes an OpenGL texture whose alpha channel is the shape of the letters.
  \item Each character on screen is one \emph{textured quad} (two triangles) whose texture coordinates
        select that character's cell in the atlas. A string is a row of such quads.
  \item \textbf{HUD text} uses an orthographic projection $\text{ortho}(0,w,h,0)$, so one unit is one pixel;
        depth testing is off, so it is always on top.
  \item \textbf{Text inside the 3D world} is drawn on a \emph{canvas}: a flat rectangle with its own model matrix
        (for example the ATM screen). A canvas point $(x,y)$ goes to the world with
        $\mathbf{p} = M_{canvas}\,(x-\tfrac{w}{2},\ y-\tfrac{h}{2},\ 0,\ 1)^T$, so the text sits exactly on the
        screen and turns with the machine. Depth testing is on, so a person walking in front hides the text.
\end{enumerate}
Text is drawn with alpha blending, $C = \alpha\,C_{text} + (1-\alpha)\,C_{behind}$, which gives smooth letter edges.

\subsection{Collision detection}
People (the player and NPCs) are \textbf{circles} on the ground. Walls, machines and furniture are
\textbf{oriented boxes} with a height range, and tree trunks and lamp posts are circles. To push a person
out of a box, the centre is turned into the box's own space (rotation by $-yaw$), the nearest point of the
box is found by clamping, $\mathbf{q}=\text{clamp}(\mathbf{p}_{local},-\mathbf{h},\mathbf{h})$, and if
$|\mathbf{p}-\mathbf{q}|<r$ the person is moved out along $\mathbf{p}-\mathbf{q}$. For two circles the
rule is the same with the distance between the centres. This is repeated up to 3 times per frame,
so corners work too. A box only counts if it overlaps the person's height (so you can walk under a
table top), and the sliding doors switch their box off while they are open. The third-person camera
casts a ray against the same boxes so it never goes through a wall.

\subsection{Sound}
Sound is kept small and simple. It uses 14 short \textbf{real recordings} that are free to use (CC0,
public domain; from Kenney.nl and OpenGameArt, listed in \texttt{assets/sounds/CREDITS.txt}). They were
trimmed, faded and levelled, and stored as 44.1 kHz mono WAV files that the program loads at start-up.
The two background sounds (birds, crickets) are loops whose end is cross-faded into their start, so they
repeat without a click. A small mixer thread adds all playing sounds together, limits the sum with
$\tanh$ (no harsh clipping) and sends blocks of 2048 samples to the sound card with the Windows
\texttt{waveOut} functions.

\subsection{Fog, frame cap and timing}
Fog is described in \Cref{sec:sky}. All movement uses the real time step $\Delta t$ of the frame, so the
speed of everything is the same at 30 or 60 FPS. The frame cap measures how long the frame took, sleeps for
most of the rest of the frame time, and then waits the last 1.5 ms in a short loop, so the frame rate is
very steady (60 or 30 FPS, selectable).

\section{The Player and the Cameras}\label{sec:camera}
\begin{itemize}
  \item \textbf{First person}: the camera is at eye height ($1.62$ m), with mouse look and a small head bob
        $0.028\sin(2\varphi)$ while walking.
  \item \textbf{Third person}: the player's own model is visible. The camera sits $3.4$ m behind the head.
        A ray from the head to the camera is tested against the walls, and the camera moves closer if a wall is in
        the way.
  \item \textbf{Free camera}: fly anywhere (W A S D, Space and Ctrl) to inspect the scene, for example
        with the roof cut-away view.
  \item \textbf{FOV}: the mouse wheel or $+/-$ changes the vertical field of view from $25^\circ$ to $110^\circ$.
        This changes the $1/\tan(f/2)$ terms of the projection matrix.
\end{itemize}
\textbf{Collision.} The player is a circle with a radius of 0.3 m. For every obstacle box (walls, furniture,
machines, cars), the circle centre is moved into the box's space, the closest point
$\mathbf{q}=\mathrm{clamp}(\mathbf{p},-\mathbf{h},\mathbf{h})$ is found, and if
$|\mathbf{p}-\mathbf{q}|<r$ the circle is pushed out along $\mathbf{p}-\mathbf{q}$ (three passes).
Tree trunks and people are circles. Gravity and jumping use $v_y \mathrel{-}= 12\,\Delta t$ on top of the terrain height.

\section{Performance on a Weak GPU}
\subsection{Techniques}
\begin{itemize}
  \item \textbf{Instanced drawing}: all copies of one basic shape are drawn with one
        \texttt{glDrawElementsInstanced} call. Each instance carries 37 floats (model matrix 16, normal matrix
        9, colour and alpha 4, emission and texture layer 4, specular, shininess, texture scale and flags 4).
  \item \textbf{Static world in chunks}: \statStaticInstances\ shapes that never move are collected once
        (in \statBuildSeconds\ s) into \statChunks\ chunks of $32\times32$ m, each with its own GPU buffer.
  \item \textbf{Culling}: a chunk is skipped if its bounding box is outside the view frustum (6 planes taken
        from the view-projection matrix) or more than 165 m away. Small things have shorter ranges:
        grass and flowers 45 m, and bushes, ferns and leaf cards 85 m.
  \item \textbf{Front-to-back order + occlusion culling}: visible chunks are drawn from near to far. For every
        chunk the GPU answers an \emph{occlusion query} (``was any pixel of it visible?''). A chunk that was
        completely hidden last frame (for example the jungle behind the back wall when you stand inside) is
        skipped. Only its bounding box is drawn, invisibly, to ask again. Results are read one frame later,
        so the CPU never waits for the GPU.
  \item \textbf{Depth pre-pass}: the scene is first drawn with a tiny depth-only shader. Then the full
        lighting shader runs with \texttt{GL\_LEQUAL} and depth writing off, so \emph{each pixel is lit exactly
        once}, instead of lighting walls, floors and leaves that are covered later. Both shaders mark \texttt{gl\_Position} as \texttt{invariant}, so the depths match exactly.
  \item \textbf{Shadow pass} only draws chunks inside the light's box, and skips grass and glass.
  \item \textbf{Per-room light lists} and frustum culling of lights (see the Lighting section).
  \item \textbf{Moving objects} are written into streaming buffers once per frame. Transparent objects are
        sorted from back to front.
  \item \textbf{Frame cap}: after each frame the program sleeps until $1/cap - 1.5$ ms and then waits the
        last moment in a loop (with a 1 ms Windows timer resolution). This gives a very steady 60 or 30 FPS
        and keeps the laptop cool.
  \item \textbf{Low mode} (\texttt{--low}): a 1024 shadow map, fewer plants, fewer visitors and no MSAA.
\end{itemize}

\section{Conclusion}
Jungle Rest Stop is a small living world: three connected rooms with working machines, visitors who come
by car and act on their own, a dense jungle and light that changes from morning to night. Every object
is a set of basic shapes placed with translation, rotation and scaling, organised in parent and child
nodes. The project covers the main topics of a graphics course in one program: transformations,
hierarchical modelling, illumination and shading, light types, textures, shadow mapping, fog,
transparency, animation, picking, collision and cameras, and it runs at a steady 60 FPS on integrated
graphics.
